== 5. Chart and securityContext changes OpenShift needed: none
values-openshift.yaml was deployed as committed; only comments changed ("not tested" to "tested on OKD 4.22").
Expected problems that did not occur on this cluster:
- RWX model PVC: the default class crc-csi-hostpath-provisioner (single node) bound llamacpp-models as RWX
  [session1-verify.txt; class in session2-cluster.txt]. A multi-node cluster still needs a real RWX class.
- Elasticsearch vm.max_map_count: 262144 on the node [session2-cluster.txt, `oc debug node/crc -q -- chroot /host
  sysctl vm.max_map_count`; the same value was seen in the first session]. So mmap stays on. A restricted-v2 pod
  cannot set this sysctl; a cluster without it would need it set on the nodes, or node.store.allow_mmap=false.
- Images without a non-root USER (llama.cpp, postgres) ran as the assigned UID with group 0 [session1-verify.txt].
What OpenShift needed outside the charts (in scripts/okd-up.sh, not in deploy/): the llm namespace labelled
argocd.argoproj.io/managed-by=argocd (the operator's ArgoCD only manages labelled namespaces), the llm-secrets Secret,
the rag image in the internal registry, the Application health check as spec.resourceHealthChecks in the ArgoCD CR
(the operator owns argocd-cm), and crc host-network-access for the git daemon.

== 8. What was tested and what was not
Tested on OKD 4.22.0-okd-scos.10 (single node, OpenShift Local): the three charts with values-openshift.yaml through
the ArgoCD app-of-apps (env=openshift); SCC restricted-v2 with UIDs from the namespace range; Routes from the host
with verified TLS; a cited chat through the rag-api Route; the llama.cpp API through its Route; the migrate and ingest
Jobs; the KEDA ScaledObject Ready with its metric; okd-up.sh re-runs on the running cluster; its host-network-access
guard.
Not tested: Red Hat OpenShift (OCP); multi-node scheduling and a real RWX storage class; OpenShift GitOps and the
Custom Metrics Autoscaler operator; KEDA scaling under load on OKD; Red Hat supported postgres and elasticsearch
images; okd-up.sh end to end on a fresh machine (the first deployment was done step by step); okd-up.sh's restart
steps after the guard fires (the same steps were done by hand in the first session).
