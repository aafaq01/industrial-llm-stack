## vLLM version research (2026-10-07)
- PyPI: newest vLLM 0.31.0 (2026-10-05). v0.31.0 CMakeLists.txt CUDA_SUPPORTED_ARCHS starts at 7.5;
  docs/getting_started/installation/gpu.cuda.inc.md: "compute capability 7.5 or higher (e.g., T4 ...)".
- v0.31.0 vllm/v1/attention/backends/flashinfer.py: FlashInfer floor raised to SM80 because it is broken on SM75
  (flashinfer issue 3620); triton_attn.py supports all capabilities -> pin --attention-backend TRITON_ATTN.
- quantization/auto_awq.py get_min_capability() == 75.
- PyPI vllm 0.31.0 requires torch==2.13.0; PyPI torch 2.13.0 depends on cuda-toolkit 13.0.3 (needs R580+ driver).
  GitHub release asset vllm-0.31.0+cu129 exists; torch/torchvision/torchaudio 2.13.0/0.28.0/2.11.0 +cu129 exist.
- uv pip compile straight from the GitHub wheel URL hung for about 3 h and was killed. The round 0 lock was then
  resolved from PyPI metadata for vllm==0.31.0 on the assumption that the +cu129 wheel had the same dependency
  list. That assumption was FALSE (found in review, fixed in round 1 below): the wheel requires
  humming-kernels[cu12] and plain nvidia-cutlass-dsl where PyPI has the [cu13] extras.
