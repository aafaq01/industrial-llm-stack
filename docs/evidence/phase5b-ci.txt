         so the llama.cpp init container could not resolve huggingface.co (kind-up-clean-attempt-3-dns.log; its last
         lines are from the next cluster, which that run's wait loop polled until its 3600 s deadline). kind-up sets

         ArgoCD wait allows 3 hours (KIND_UP_TIMEOUT) because a first run downloads the 1.1 GB model in the cluster.
e1c067a  `git archive --mtime=@0` is read by git as "now", and Git for Windows (core.autocrlf=true) converted rag/
         text files to CRLF because rag/ alone has no .gitattributes. Now core.autocrlf=false and an explicit date;
         the archive of a290dea:rag is byte-identical from Git for Windows 2.53 and git 2.47 in Jenkins (sha256
         daeb8c97...). Only the CRLF difference changed the image: BuildKit's cache key ignores mtimes.

The ArgoCD wait (scripts/gitops-publish.sh) fails only when its deadline passes (3600 s by default, 3 hours from
kind-up), not early when an app is Degraded: a Degraded app that later becomes Healthy still passes.
