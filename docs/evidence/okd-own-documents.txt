What happened, in order (nothing hidden)
  1. The saved crc VM (created 2026-10-10) had been stopped for days. crc start failed: kubelet serving certificate expired and could not be
     renewed ("still expired (x58)"). I ran crc delete and let okd-up.sh create a fresh VM from the cached bundle (the VM only held this project).
  2. Fresh start worked (about 15 min). okd-up.sh then stopped at "timed out: has_installplan" after 5 min: the operator catalog was still unpacking.
     Re-running the script was enough.
  3. The ArgoCD repo-server image pull inside the VM took 12m15s; Elasticsearch, llama.cpp and the 1.1 GB model took until 08:26Z (about 36 min after sync).
  4. The root Application's sync used up its 5 retries while wave 1 was still pulling, so rag-api was never created. I re-triggered the sync by patching
     an operation onto the root Application (revision 62d904a). Not done by the script; a script fix is not made.
  5. The ingest pod stayed Pending ("Insufficient memory": node requests 94% of 16 GB). I raised the VM to 20 GB (crc config set memory 20480, stop,
     start) and changed okd-up.sh to set memory=20480. The earlier OKD run in docs/evidence/v3-openshift-okd.txt fitted in 16 GB; why this one did not
     was not investigated (more pods requesting memory since then is one guess).
  6. After the manual crc start my ~/.kube/config had no crc context. I merged crc's own kubeconfig (backup at ~/.kube/config.bak-before-crc-merge), then
     logged in as kubeadmin (token) and named the context crc-admin, which the script expects. okd-up.sh then finished: "done in 13m8s", exit 0,
     all four ArgoCD apps Synced/Healthy.
