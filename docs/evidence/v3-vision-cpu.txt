#!/usr/bin/env bash
# Vision CPU baseline driver: host sampler + cpu_baseline.sh twice (ORT default threads, then 4 intra-op threads).
set -euo pipefail
cd /c/Users/<user>/Desktop/work/industrial-llm-platform
S=$1 OUT=$2
W=$(cygpath -w "$S")
ONNX=benchmark/results/raw/kaggle-20261010-v3c/results/models/yolov8n-fp32-opset17.onnx
HW="Windows 11 host, AMD Ryzen 7 7730U (8C/16T), ONNX Runtime CPU, native Windows Python"
rm -f "$S/stop"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$W\hostsampler.ps1" -Out "$W\host-samples.csv" \
  -TopOut "$W\host-top-processes.txt" -Stop "$W\stop" &
SAMPLER=$!
sleep 20
echo "start $(date -u +%FT%TZ)"
bash benchmark/vision/cpu_baseline.sh "$ONNX" "$HW" "$OUT" \
  --notes "ORT default intra-op threads (intra_op_num_threads 0 = ORT chooses)"
echo "default threads done $(date -u +%FT%TZ)"
THREADS=4 bash benchmark/vision/cpu_baseline.sh "$ONNX" "$HW" "$OUT" \
  --label vision-cpu-yolov8n-onnx-fp32-t4 --notes "ORT intra_op_num_threads fixed at 4"
echo "end $(date -u +%FT%TZ)"
sleep 20
touch "$S/stop"; wait $SAMPLER || true
echo "sampler stopped $(date -u +%FT%TZ)"

## Flags and observations
- No flags on any CPU cell: 3 repeats each, 0 errors, CV on images/s at most 0.022 (4-thread b32: 17.7, 18.4,
  18.4), same model sha256, config and git commit across repeats.
- Throughput does not grow with batch on CPU: 23.1 (b1), 19.8 (b8), 19.3 (b32) images/s with default threads; the same
  shape with 4 threads (21.3, 18.6, 18.2). On the T4 the ORT CUDA path goes 162.3, 187.0, 180.5. A plausible reason
  is cache and memory pressure from larger activations on CPU; not investigated.
- Default (about 8) threads beat 4 threads by only 6 to 9% (b1 23.1 vs 21.3, b8 19.8 vs 18.6, b32 19.3 vs 18.2). The processor performance counter was
  lower with more cores busy (118 to 124% of base clock vs 127 to 138% for 4 threads), consistent with lower boost
  clocks under wider load. Run order is a confound: the 4-thread runs came second, with the ACPI zone at 79 to 81 C
  vs 76 to 79 C.
- Host CPU while measuring: 61 to 70% mean per run with default threads, 31 to 45% with 4 threads, the benchmark
  itself included. Other processes in the top-process samples: cursor up to 6.9% (14:04:22), vmmemwsl (the WSL2 VM,
  with only the idle BuildKit container running) 10.9 to 17.0% at 14:05:17, 14:08:03 and 14:09:54, Docker Desktop
  3.7%, svchost 3.1%. The vmmemwsl bursts are unexplained. They overlap default b32 r2 (14:05:05 to 14:05:55),
  4-thread b1 r3 (14:07:49 to 14:08:19) and 4-thread b8 r3 (14:09:37 to 14:10:15); those three runs are within 1.6%
  of their cell means.
- CPU vs GPU is not like for like (laptop CPU FP32 vs T4; different host, OS, driver stack). Side by side only:
  ORT CPU b1 23.1 images/s vs ORT CUDA b1 162.3 and TensorRT FP16 b1 295.1 on the T4, same ONNX file for the two ORT
  rows.
